# Konvin v4 — 네트워크 라이브러리 스펙 (초안)

같은 네트워크에 있는 여러 컴퓨터의 Konvin 라이브러리를 서로 찾아보고
가져올 수 있게 하는 기능. 서버와 계정 없이, 두 컴퓨터가 같은 네트워크에
동시에 켜져 있을 때만 동작한다.

## 목표 / 비목표

- 목표: 같은 네트워크의 다른 PC가 가진 영상을 찾아보고 수동으로 가져오기
- 목표: 서버 비용 없이 순수 P2P 로 동작
- 목표: 기존 UI 를 크게 바꾸지 않기 (상단 탭 2개 추가 수준)
- 비목표: 인터넷 너머 동기화, 서로 다른 네트워크 간 동기화
- 비목표: 아이튠즈식 자동·상시 동기화 (항상 수동 요청·승인 기반)

## UI 변경

기존 메인 창은 그대로 두고 상단에 탭 2개만 둔다.

- **내 라이브러리** — 지금까지의 다운로드·변환 화면
- **네트워크** — 발견된 다른 Konvin PC 목록 → 클릭하면 그 PC 의 영상
  목록 → 체크 후 "가져오기"

가져온 파일은 기존 다운로드 폴더에 그대로 떨어뜨린다. 별도 보관 위치를
만들지 않는다.

## 아키텍처

### 1) 발견 (Discovery)

- `zeroconf` 패키지로 `_konvin._tcp.local.` 서비스를 등록하고 탐색한다
- 광고에 싣는 정보: 기기 이름(최초 실행 시 사용자가 정함), 기기 UUID,
  HTTP 포트
- 앱이 켜져 있는 동안 계속 광고 + 탐색 (백그라운드 QThread)

### 2) 로컬 HTTP 서버

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/videos` | 보유 영상 목록 (id, 제목, 크기, 날짜) |
| POST | `/request` | 다운로드 요청 등록 → 요청 ID 반환, 대기 상태 |
| GET | `/request/{req_id}/status` | 요청 상태 (대기/허용/거부/만료) |
| GET | `/download/{token}` | 허용된 요청의 토큰으로 파일 받기 |

파일 id 는 서버 내부 인덱스에서만 실제 경로로 바꾼다. 요청에 들어온
값을 파일 경로에 직접 쓰지 않는다 (경로 순회 방지).

### 3) 요청 · 승인 흐름

1. 요청 측이 `/request` 로 파일 id 를 보낸다 → 대기 상태로 등록
2. 응답 측 화면에 확인 창이 뜬다
   - 내용: "○○PC 가 'xxx.mp4'(320MB)를 요청했습니다"
   - 버튼: 거부 / 허용
   - 체크박스: "이 컴퓨터는 항상 허용"
     - 경고 문구를 함께 보여준다:
       "체크하면 이후 승인 없이 파일에 자동으로 접근할 수 있게 됩니다.
       신뢰하는 내 컴퓨터에만 사용하세요."
   - 30초 무응답이면 자동 거부
3. 허용되면 일회성 토큰(uuid4)을 발급하고 요청 상태를 갱신
4. 요청 측이 상태를 확인한 뒤 `/download/{token}` 으로 파일을 받는다
5. 토큰은 한 번 쓰거나 5분이 지나면 소멸

### 4) 신뢰 목록

- "항상 허용" 체크 시 요청 측 기기 UUID 를 `trusted_devices.json` 에 저장
- 이후 그 기기의 요청은 확인 창 없이 바로 토큰 발급
- 네트워크 탭에서 신뢰 목록을 보고 개별 "신뢰 해제" 가능
- 해제하면 다시 확인 창을 거친다

### 5) 기기 인증과 암호화 (프로토콜 5)

위 1)~4) 는 처음 설계 그대로이고, 아래가 그 위에 얹혔다. 프로토콜 4 와는
호환되지 않는다 (지문을 광고하지 않는 기기는 목록에 올리지 않는다).

- **인증서**: 기기마다 처음 켤 때 자체 서명 인증서(EC P-256)를 만든다.
  인증서의 SHA-256 지문이 그 기기를 가리키는 값이고, 광고에 함께 싣는다
- **암호화**: 서버는 TLS 1.3 만 받는다. 붙는 쪽은 인증 기관 대신 지문을
  직접 비교하고, 다르면 요청을 보내기 전에 끊는다
- **페어링**: 처음 만난 기기끼리 한 번 한다. 요청한 쪽 화면의 6자리 코드를
  받는 쪽에 입력해야 한다
  1. A → B `POST /pair/start` : A 의 ID·이름·지문, 그리고 무작위 값 na 의
     해시(약속)
  2. B → A : 무작위 값 nb
  3. A → B `POST /pair/reveal` : na 공개. B 는 약속과 맞는지 확인
  4. 양쪽이 (A 지문, B 지문, na, nb) 로 코드를 계산. A 는 실제로 연결된
     서버 인증서의 지문을 쓴다
  5. B 에서 코드가 맞으면 비밀키(32바이트)를 만들어
     `GET /pair/{id}/status` 응답으로 한 번만 넘긴다
  약속을 먼저 보내게 한 것은, 가운데에 낀 기기가 상대의 무작위 값을 본 뒤
  자기 값을 골라 코드를 맞추는 일을 막기 위해서다
- **요청 인증**: `/videos`, `/request`, `/request/…/status`, `/download/…`
  는 페어링된 기기만 쓸 수 있다. 요청마다
  HMAC-SHA256(비밀키, 메서드·경로·일회용 값·서버 지문) 을 머리말에 싣는다
- **항상 허용**: 서명으로 확인된 기기에만 적용된다. 신뢰 목록에 ID 가
  있어도 페어링이 없으면 아무 효력이 없다
- **토큰**: 발급받은 기기만 쓸 수 있다
- **받는 쪽 방어**: 파일 이름에서 디렉터리 부분을 떼고, 목록에서 본 크기와
  `Content-Length` 가 다르면 받지 않으며, 그 크기를 넘겨 읽지 않는다.
  파일 하나의 상한은 4GB
- **서버 방어**: 랜 주소 하나에만 연다. 동시 연결 32개, TLS 악수 5초,
  요청 본문 64KB, 승인 대기 20건, 페어링 창은 한 번에 하나이고 거부한 뒤
  30초 동안은 새로 띄우지 않는다

저장 파일 (`~/Konvin`): `net_cert.pem`, `net_key.pem`,
`paired_devices.json` — 뒤의 둘은 주인만 읽을 수 있게(0600) 쓴다.

### 6) 알려진 한계

- 페어링의 안전성은 사람이 코드를 직접 보고 입력하는 데 달려 있다.
  받는 쪽에서 코드를 입력한 적이 없는데 요청한 쪽에서 페어링이 됐다고
  나오면, 진짜 상대가 아닌 기기와 페어링된 것이다
- 6자리 코드라서 가운데에 낀 기기가 한 번의 시도에서 우연히 맞을 확률이
  100만분의 1 있다
- 기기 이름과 지문은 광고로 누구에게나 보인다. 네트워크 공유를 켜 둔
  동안에는 이 컴퓨터가 Konvin 을 쓰고 있다는 사실이 같은 네트워크에 드러난다
- 같은 네트워크의 기기가 연결을 계속 쏟아부으면 그동안 다른 기기가 붙지
  못할 수 있다 (정보가 새지는 않는다)
- 상대 PC 가 꺼져 있으면 그 파일에는 접근할 수 없다

## 데이터 모델

- `library.json` — 로컬 다운로드 이력 인덱스 (id, 제목, 경로, 크기, 날짜).
  지금의 폴더 스캔 방식을 이걸로 정리하면 `/videos` 응답도 단순해진다
- `trusted_devices.json` — 신뢰 기기 UUID 목록
- `paired_devices.json` — 페어링된 기기의 이름·지문·비밀키

## 구현 순서

1. 발견 프로토콜 검증 — zeroconf 로 두 PC 가 서로 찾는지 CLI 로 실험
2. 로컬 HTTP 서버 골격 — `/videos` 만 먼저, 인증 없이
3. 요청·승인·토큰 흐름 + 확인 창 UI
4. 신뢰 목록 저장·해제 UI
5. 메인 창에 "네트워크" 탭 추가
6. 에러 처리 (방화벽 차단, 응답 없음, 전송 중단)
